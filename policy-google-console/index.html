Google Console — CI/CD API usage & permissions

Purpose: This page documents which Google APIs and permissions are required by the project's GitHub Actions workflows and why those permissions are needed. The CI/CD pipeline uploads build artifacts (Android app binaries) to Google Drive and uploads video assets to YouTube after builds. This document also explains how credentials are stored and recommended security/consent steps for Google verification.

APIs to enable in Google Cloud Console

  • YouTube Data API v3 — required to upload videos and manage video metadata.
  • Google Drive API — required to upload built artifacts (APK / AAB) or store build artifacts in Drive.

OAuth scopes required

Use the principle of least privilege: only request the specific scopes you need.

  • https://www.googleapis.com/auth/youtube.upload — upload videos to YouTube (recommended minimal scope for uploads).
  • https://www.googleapis.com/auth/youtube — broader YouTube scope (only request if you need channel management beyond uploads).
  • https://www.googleapis.com/auth/drive.file — allow the app to create and manage files it has created or opened (preferred to avoid full-drive access).

Authentication options for CI

Two common approaches for GitHub Actions:

  1. OAuth client + refresh token (recommended for YouTube uploads):

    YouTube uploads normally require OAuth on behalf of a channel owner — service accounts cannot access YouTube channels. Create OAuth client credentials (Web or Other), perform one-time interactive consent to generate a refresh token for the target YouTube account, then store the refresh token and client credentials as encrypted GitHub secrets. The workflow exchanges the refresh token for access tokens during runs.

  2. Service account (possible for Drive only):

    For Drive uploads where a service account can be authorized to a Drive folder or Google Workspace domain, use a service account JSON key (stored as a GitHub secret) and use the Drive API with that service account. This does not work for uploading to a personal YouTube channel.

Important: YouTube uploads require OAuth consent by the channel owner. If you request sensitive or restricted scopes, Google will require verification of the OAuth consent screen and a privacy policy URL.

What data is accessed and stored

  • Uploaded video files and metadata (title, description, thumbnails) are stored on YouTube and are subject to YouTube's policies.
  • Build artifacts (APK, AAB, logs) uploaded to Google Drive are stored in the Drive account/folder used by the workflow.
  • Authentication tokens/keys (OAuth client ID/secret, refresh token, or service account JSON) are stored only as encrypted GitHub repository secrets. The actions runner obtains tokens at runtime and uses them temporarily; tokens are not committed to the repo.
  • Action logs may contain minimal metadata about the upload; avoid echoing secrets in logs.

Security & best practices

  • Store credentials in GitHub Actions secrets (Repository/Organization secrets) and never commit keys to source control.
  • Use least-privilege scopes: prefer drive.file instead of full drive, and only request YouTube scopes needed for upload.
  • Rotate keys and refresh tokens regularly and immediately after suspected compromise.
  • Limit which repositories and workflows can access organization-level secrets (use environments and required reviewers if needed).
  • Restrict service-account access to a specific Drive folder and grant minimal roles (e.g., roles/drive.file via IAM) when possible.
  • Do not print secrets or tokens to CI logs.

OAuth consent & verification notes

When setting up OAuth consent screen in Google Cloud Console:

  • Provide a clear Application name and Support email.
  • Authorized domains should include the domain hosting this project's privacy policy (for GitHub Pages use your github.io domain or a custom domain).
  • Provide a valid Privacy Policy URL (this project must include a privacy policy page that explains how user data and uploaded files are handled).
  • If you request sensitive scopes (YouTube upload qualifies), Google may require verification which can take several days and asks for demonstration videos, justification, and a privacy policy.

Example workflow notes (high level)

  • After build completes, the workflow authenticates (exchange refresh token for access token or use service account credentials) and uploads the artifact to Drive or uploads a video to YouTube via the YouTube Data API.
  • Use existing open-source GitHub Actions for YouTube upload or Drive upload when possible; inspect their implementation and scope usage before trusting them.
